# 演示视频脚本（约 4 分 30 秒）

> 录制前：使用演示数据目录（`npm run reset` 后 `npm start`）；关闭 `.env` 编辑器标签、清理终端历史，避免密钥入镜。没有 API Key 时界面会显示“模拟模式”，旁白要如实说明。
> 截图参考：`docs/assets/ui-*.png`。

| 时间 | 画面 | 旁白要点 |
|---|---|---|
| 0:00–0:20 | 登录页：每个角色一个测试账号（点“填入”再点“登录”）；首页工作流列表；侧边栏“模拟模式 / 真实模型”标识；使用者的侧边栏没有“审核与审批”和“规则包” | 营销物料合规初审又慢又不一致；这是让法务团队自己搭建 AI 审阅流程的原型，以新加坡营销物料为验证场景 |
| 0:20–0:50 | 审核人打开示例规则包：来源、核实程度；签署审核声明（姓名、资格、复审日期） | 规则是可审核的数据；未经批准的规则包不能用于正式运行（ui-02、ui-03） |
| 0:50–1:30 | 创建者新建 Skill：任务说明、输入、输出字段；样例测试成功；提交审核，提交人看不到“批准”按钮 | 不写代码；输出结构是步骤之间的契约；发布需要另一个人批准（ui-05、ui-06） |
| 1:30–2:00 | 工作流编辑器：把新 Skill 接到“对照规则检查”之后作为并行分支；故意去掉一个依赖，让输入映射引用了非上游节点，编辑器立即标红并指出字段 | 错误在创建时就被发现，不等到运行（ui-07） |
| 2:00–2:50 | 使用者上传 PDF 运行：节点实时变化；打开“对照规则检查”：引文带页码、“优先复核 / 常规复核”、安全防护记录；停在法务审批节点，第二位审核人批准 | 可信来自确定性核对和人工判断，不是“再问一遍 AI”（ui-10、ui-11、ui-22） |
| 2:50–3:20 | 异常：不填物料提交被拦；在材料中加入 `[[MOCK:429]]` 运行，显示“限流，已自动重试 2 次”；点“从失败节点重试”，前序节点显示“复用” | 失败也是设计的一部分（ui-15、ui-16、ui-24） |
| 3:20–4:00 | 修改 Skill → 审核发布 v2 → 重新运行仍用钉住的 v1 并提示可升级 → 重新提交工作流审批后用 v2；打开“对比运行”；刷新页面配置仍在 | 批准什么就运行什么；版本可比较（ui-25、ui-27） |
| 4:00–4:30 | Skill 页“评测与受控优化”：评测草稿 → 生成优化候选 → 门控结果；最后展示已知限制 | 评测集分训练 / 留出；候选必须过门控并由人采用。模拟模式下候选没有提升，被门控拦住——这正好说明门控在起作用（ui-26） |
