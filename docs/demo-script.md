# 演示视频脚本（约 4 分 30 秒，v3.2）

> 按“痛点 → 创建 Skill → 组合工作流 → 运行看结果 → 异常 → 修改重跑 → 收尾”七段录制。正式录制用 DeepSeek 真实模型，视频本身即可作为题目要求的“一次真实模型调用的端到端演示”。截图参考：`docs/assets/ui-*.png`。

## 录制前准备

- `npm run reset` 后 `npm start`，得到干净的演示数据；`.env` 填 `DEEPSEEK_API_KEY`，确认侧边栏显示“真实模型 deepseek / deepseek-flash”。
- 先不填密钥，用模拟模式完整排练一遍；正式录制前确认 DeepSeek 账户余额。
- 真实模型比模拟慢：建议设 `LLM_TIMEOUT_MS=180000`；等待节点完成的片段剪掉，并在画面上标注“已剪辑等待”。
- 两个浏览器窗口（普通 + 无痕），按 README 的测试账号表分别登录创建者、审核人、使用者；第二位审核人（reviewer2）用来演示四眼原则。v3.2 起同一浏览器的不同标签页也可以登录不同账号，互不影响。
- 画面里不出现 `.env`、终端历史和密钥；浏览器放大到 125%，关闭通知，1080p 录制。交付后把演示用的 DeepSeek 密钥作废。
- 预案：真实调用失败（余额、网络）时切回模拟模式继续录，在视频里如实说明，并另附 `npm run demo:real` 生成的运行记录（`docs/evidence/real-run-*`）。

## 分镜与旁白

| 时间 | 画面（操作） | 旁白要点 |
|---|---|---|
| 0:00–0:20 | 登录页的测试账号表；登录后进入对话首页，侧边栏显示“真实模型 deepseek-flash”，左侧保留工作流、Skills、运行记录等入口 | 营销物料初审又慢又不一致；这是让法务团队自己搭建 AI 审阅流程的原型，以新加坡营销物料为验证场景；创建者、审核人、使用者各用各的账号（ui-00、ui-28） |
| 0:20–1:10 | 创建者新建 Skill（如“面向市场部的整改清单”）：任务说明、输入字段、输出要求；用样例测试成功；保存并提交；审核人批准（提交人看不到“批准”按钮） | 不写代码；输出字段是步骤之间的契约；发布必须由另一个人批准（ui-05、ui-06） |
| 1:10–1:50 | 工作流编辑器：添加 AI 节点，依赖“对照规则检查”成为并行分支；为输入选择上游字段；故意引用非上游节点，编辑器立即标红；保存、提交、审批 | 前一步的输出传给后一步；配置错误在创建时就被发现（ui-07） |
| 1:50–2:50 | 使用者登录（没有审核区和编辑区，ui-01），在对话首页上传“两页 EDM（PDF）”并发送；运行卡片实时打印每一步，鼠标移到节点上看处理信息（ui-29）；停在“法务负责人审批”，第二位审核人批准后结果出现在对话里并一直保留（ui-30）；点“追问这次结果”问一条问题（ui-31）；打开完整运行页：引文带页码、优先 / 常规复核，逐条采纳或修改 | 信任来自确定性核对和人工判断，不是“再问一遍 AI”；结论核验只决定复核顺序；过程全程可见（ui-10、ui-11、ui-22） |
| 2:50–3:20 | 不填材料直接运行（字段标红）；测试运行里给“对照规则检查”注入“限流”，显示已重试次数和处理建议；点“从失败节点重试” | 失败也是设计的一部分；重试复用已成功的节点（ui-15、ui-16、ui-24） |
| 3:20–4:00 | 修改 Skill → 审核发布 v2 → 重新运行（仍用钉住的 v1 并提示可升级）→ 重新提交工作流审批后用 v2；“对比运行”；刷新页面配置仍在 | 满足“修改并再次运行”；批准什么就运行什么（ui-25、ui-27） |
| 4:00–4:30 | 运行页点“回放过程”，拖动进度条看流程图随时间着色（ui-34）；导出报告；一句话带过评测与受控优化；展示已知限制 | 每次运行的过程都留档、可回看；诚实收尾：示例规则包未经执业律师审核；核验不能证明法律结论正确；下一步的三件事（ui-26） |

必须拍到的是前四段（题目要求的“创建 Skill → 组合 Workflow → 执行并查看结果”）；超时就压缩第 6 段。第 7 段必须说清哪些是真实模型的结果、哪些是模拟。
