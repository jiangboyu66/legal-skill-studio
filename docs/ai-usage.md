# AI 使用说明

> 本文件记录本项目中 AI 的使用方式，以及 AI 产出被验证、修改或否定的真实例子。以下条目均来自本项目开发会话中实际发生的事件；**提交前请候选人逐条核对、补充自己的判断与其他工具的使用记录，并保留会话记录，不要删除**。

## 1. 使用范围

| 环节 | AI 做了什么 | 人做了什么 |
|---|---|---|
| 方案准备 | 《执行指南与设计方案》（48 页）由 AI 生成（指南正文自述） | 决定以它为对照清单，但逐条核实与取舍（见第 2 节、docs/06） |
| 调研 | AI 检索开源项目、法规与监管指引，整理来源 | 规则包中每条规则保留来源链接与“原文 / 转述 / 未核实”标记；未核实的不冒充原文 |
| 编码与测试 | 代码、测试、脚本主要由 AI 编码代理（Claude）在对话中生成并运行 | 三次关键指令：按题目完成项目并先调研开源复用；修复五个限制并按 cc-src-learning 重构架构；对照执行指南找出差距并改进 |
| 文档 | AI 起草 docs/ 下的说明、ADR 与本文件 | 对最终方案负责，需能解释每个关键决策 |

## 2. 对执行指南建议的取舍（采纳 / 修改 / 否定）

| 指南建议 | 处理 | 理由 |
|---|---|---|
| 发送前可逆假名化、随机边界、金丝雀、外链图片拦截、S1–S6 安全测试 | 采纳 | 这是 v2 的真实缺口；全部实现并有自动化测试 |
| 训练 / 留出划分、F2、门控 + 人工批准的优化流程 | 采纳（轻量版） | 不做 LLM 评审分 J，避免“用 AI 评 AI” |
| 澄清问题不超过 5 个 | 采纳 | v2 写了 10 个，违反题目要求，已合并 |
| MVP 只做线性 Workflow | 否定 | 上一轮需求明确要求修复“只能线性”；见 ADR 0001 |
| 模型不给工具 | 修改 | 给只读、不联网的工具；见 ADR 0003 |
| Python / FastAPI 技术栈 | 否定 | 保持 TypeScript 全栈；见 ADR 0002 |
| `model_config.temperature = 0` | 否定 | 核实后发现 Claude 4.7 及以后的模型对非默认采样参数返回 400；不发送该参数 |
| 错误码改名为 `E_*` | 修改 | 不改名，提供一一对应表（docs/04 §3.3），避免无行为变化的大范围改动 |
| 引用 [2025] SGHCR 33 说明“AI 核查 AI 不充分” | 核实后采纳 | 打开 eLitigation 判决书确认：第 [39] 段援引法院生成式 AI 指南第 5(3)(e) 段；第 [99] 段个人承担 S$800 讼费 |

## 3. AI 产出被测试或核查推翻的真实例子

| 时间 | AI 最初的做法 | 怎么发现的 | 改成了什么 |
|---|---|---|---|
| 2026-10-31（v3.1） | 端到端场景 1 在页面跳转后立即检查“新建 Skill”按钮是否可见，没有等页面加载完 | 重复运行时偶发失败（19/20） | 先等待列表出现再断言；之后连续两次 20/20 |
| 2026-10-31（v3.1） | 字段编辑器改为两行卡片后，在 900px 宽的窗口里，编辑页窄栏中的“显示名称”和类型下拉仍被截断（显示为“文档 / …”） | 浏览器截图人工检查 | 增加容器查询：栏宽不足时名称、类型各占一行，不再截断 |
| 2026-10-31（v3.1） | 使用者的 Skill 概览中，没有说明但有子字段的输出项同时显示“—”和“每一项包含：…” | 浏览器截图人工检查 | 只有既没有说明也没有选项 / 子字段时才显示“—” |
| 2026-10-31（v3.1） | “补充漏项”的规则编号输入框没写 `type`，全局输入框样式对它不生效 | 改输入框样式时逐个检查 | 补上 `type="text"`，全局样式也覆盖没有 `type` 的输入框 |
| 2026-10-31（v3） | 金丝雀检测拦截了输出，但泄露的系统提示词仍留在“AI 过程”记录里（`submit_output` 的调用参数） | 新写的安全测试断言过程记录中不得出现金丝雀，测试失败 | 增加过程记录过滤器：疑似泄露的条目在保存和实时推送前替换为占位文字 |
| 2026-10-31（v3） | 密钥扫描对同一个假密钥报告两次（两个模式重叠） | S6 测试期望 1 条，实际 2 条 | 每行只报告第一个命中的模式 |
| 2026-10-31（v3） | 假名化摘要显示“NRIC/FIN ×2”，而材料里只有一个号码 | 测试断言 ×1 失败；原因是同一号码同时出现在“声明”和“材料”两个输入中 | 摘要改为统计不同的值，出现次数单独记录 |
| 2026-10-31（v3） | 原有测试断言“Skill 发布 v2 后，工作流正式运行立即使用 v2” | 实现版本钉住后该测试失败——旧断言描述的恰恰是要修复的问题 | 改为断言：仍用钉住的 v1 并提示可升级；重新审批工作流后才用 v2 |
| 2026-10-31（v3） | 端到端“运行对比”场景比较了两份不同物料的运行（共同 0 条），场景通过但没有意义 | 人工查看结果说明 | 改为比较同一物料在 Skill v1 / v2 下的运行，并断言共同条数 > 0 |
| 2026-10-31（v3） | 计划在文档中直接引用指南里的判例结论 | 写入前先检索并打开判决书 | 确认段落号后才引用，并附原始来源链接 |
| v2 开发期间 | `demo:real` 在伪造接口上的试运行结果被写入 `docs/evidence/` | 复查证据目录时发现这些结果不是真实模型输出 | 删除，不放入证据；文档明确写“本环境未执行真实调用” |
| v2 开发期间 | 计划表中有一列“实际用时”，数值并非实测 | 复查文档时发现 | 删除该列，避免伪造数据 |
| v2 开发期间 | OCR 引文近似匹配按词比较，两个字符识别错误就匹配失败 | 用真实 OCR 结果做的测试失败 | 改为编辑距离（≤ 15%）的子串近似匹配；v3 又把近似匹配标为“需核实”，不算通过 |
| v2 开发期间 | NRIC 告警信息显示的号码遮挡不足，且粘贴的材料被统计两次（原文 + 转存的文档） | 测试与人工查看 | 改为只显示首尾各一位、粘贴的材料只统计一次；v3 进一步改为发送前假名化 |
| v2 开发期间 | 核验代理的工具调用没有写入运行记录 | 检查运行记录时发现缺失 | 核验代理的过程以 `verifier/` 前缀并入节点记录 |

## 4. 验证纪律

- **每个功能都有测试**：96 项自动化测试 + 20 个浏览器场景；修复缺陷时先让测试复现失败。
- **不伪造证据**：模拟模式的结果在界面、报告、评测报告中都标注“模拟”；没有真实 API Key 就不声称做过真实调用；运行记录由系统导出，不手工编辑。
- **来源要能打开**：引用的法规、判例、API 变化都先打开原始页面或可信的二手来源确认，并附链接。
- **安全清单逐项检查**：密钥只来自环境变量（`npm run check:secrets` 扫描源码与前端构建产物）；材料按数据处理；输出不加载外部资源。
