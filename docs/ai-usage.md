# AI 使用说明

> 本文件记录本项目中 AI 的使用方式，以及 AI 产出被验证、修改或否定的真实例子。以下条目均来自本项目开发会话中实际发生的事件；**提交前请候选人逐条核对、补充自己的判断与其他工具的使用记录，并保留会话记录，不要删除**。

## 1. 使用范围

| 环节 | AI 做了什么 | 人做了什么 |
|---|---|---|
| 方案准备 | 《执行指南与设计方案》（48 页）由 AI 生成（指南正文自述） | 决定以它为对照清单，但逐条核实与取舍（见第 2 节、docs/06） |
| 调研 | AI 检索开源项目、法规与监管指引，整理来源 | 规则包中每条规则保留来源链接与“原文 / 转述 / 未核实”标记；未核实的不冒充原文 |
| 编码与测试 | 代码、测试、脚本主要由 AI 编码代理（Claude）在对话中生成并运行 | 七轮关键指令：① 按题目完成项目并先调研开源复用（v1）；② 修复五个限制并按 cc-src-learning 重构架构（v2）；③ 对照执行指南找出差距并改进（v3）；④ 接入 DeepSeek flash、每个角色独立测试账号、收窄使用者界面、修正输入框提示溢出（v3.1）；⑤ 整理交付：简要说明文档、演示视频指引、AI 使用环节；⑥ 运行时实时打印进度或悬停节点显示处理信息、修复运行完之后结果消失、运行记录可回看与回放、首页改为对话框并保留左侧功能（v3.2）；⑦ 新对话栏并入左侧功能栏、“深度思考”打印运行思考、发送按钮兼作停止工作流（v3.3） |

## 2. 对执行指南建议的取舍（采纳 / 修改 / 否定）

| 指南建议 | 处理 | 理由 |
|---|---|---|
| 发送前可逆假名化、随机边界、金丝雀、外链图片拦截、S1–S6 安全测试 | 采纳 | 这是 v2 的真实缺口；全部实现并有自动化测试 |
| 训练 / 留出划分、F2、门控 + 人工批准的优化流程 | 采纳（轻量版） | 不做 LLM 评审分 J，避免“用 AI 评 AI” |
| 澄清问题不超过 5 个 | 采纳 | v2 写了 10 个，违反题目要求，已合并 |
| MVP 只做线性 Workflow | 否定 | 上一轮需求明确要求修复“只能线性”；见 ADR 0001 |
| 模型不给工具 | 修改 | 给只读、不联网的工具；见 ADR 0003 |
| Python / FastAPI 技术栈 | 否定 | 保持 TypeScript 全栈；见 ADR 0002 |
| `model_config.temperature = 0` | 否定 | 核实后发现 Claude 4.7 及以后的模型对非默认采样参数返回 400；不发送该参数 |
| 错误码改名为 `E_*` | 修改 | 不改名，提供一一对应表（docs/04 §3.3），避免无行为变化的大范围改动 |
| 引用 [2025] SGHCR 33 说明“AI 核查 AI 不充分” | 核实后采纳 | 打开 eLitigation 判决书确认：第 [39] 段援引法院生成式 AI 指南第 5(3)(e) 段；第 [99] 段个人承担 S$800 讼费 |

## 3. AI 产出被测试或核查推翻的真实例子

| 时间 | AI 最初的做法 | 怎么发现的 | 改成了什么 |
|---|---|---|---|
| 2026-11-01（v3.3） | 输入框的上传按钮、占位文字用了回形针 emoji（📎） | 用户截图：Windows 上显示成另一种图形 | 改为内置 SVG 图标（回形针、发送、停止、深度思考），不依赖系统 emoji 字体 |
| 2026-11-01（v3.3） | 写停止功能的测试时，预期“另一位创建者停止使用者的运行”返回 404、对已停止运行的审批返回 404 | 测试失败：创建者有“查看全部运行”权限，能看到这条运行，正确结果是 403（不是发起人）；审批节点已被跳过，正确结果是 409 | 修改测试预期，并在文档中写明只有发起人或管理员能停止 |
| 2026-11-01（v3.2） | 收到“运行完之后结果消失”后，先在模拟模式下照常运行来复现，没有复现，差点把它当成真实模型特有的问题 | 注意到用户截图里开着两个本应用的标签页；用 v3.1 在同一浏览器里一个标签页看运行、另一个标签页换账号登录，整页变成“运行记录不存在” | 确认根因是共享 Cookie + 刷新失败清空整页（docs/04 §3.4）；改为按标签页的会话，刷新失败只提示不清空；新增端到端场景 23 |
| 2026-11-01（v3.2） | 为让进度更快显示，把推送来的节点状态直接写入页面 | 端到端场景 6、9、12、15 超时；排查发现节点先变成“等待审批”时审批请求还没加载，审批面板报错 | 否定这一做法：推送只追加日志与过程记录，状态变化一律重新加载；审批面板对缺失数据容错；补单元测试 |
| 2026-11-01（v3.2） | 对话页的输入区随对话 ID 重新挂载；对话数据直接用最近一次请求的结果 | 自查代码时发现：第一次发送会新建对话并改变地址，发送失败的错误提示落在已卸载的组件上；较慢的读取可能用旧对话覆盖刚收到的回复 | 输入区不再重新挂载；只接受不比当前更新时间更旧的对话 |
| 2026-11-01（v3.2） | 对话页的网格只设了高度、没有限定行高，内容变长后输入框被挤出屏幕 | 浏览器截图人工检查 | 网格行设为 `minmax(0, 1fr)`，消息区单独滚动，输入框固定在底部 |
| 2026-11-01（v3.2） | 模拟模式的追问回答把 Markdown 报告原样压成一行 | 浏览器截图人工检查 | 改为概述报告开头，并优先列出“对照规则检查”的问题清单 |
| 2026-10-31（v3.1） | 登录页提供“一键登录”按钮，所有演示账号共用密码 `demo1234` | 人审阅界面时否定：“每个不同权限账户给出对应的测试账户和密码，不是直接切换” | 每个角色独立密码；“填入”只填表单，仍需点“登录”；v3.0 旧数据启动时自动迁移 |

## 4. 验证纪律

- **每个功能都有测试**：137 项自动化测试 + 25 个浏览器场景；修复缺陷时先让测试复现失败。
- **不伪造证据**：模拟模式的结果在界面、报告、评测报告中都标注“模拟”；没有真实 API Key 就不声称做过真实调用；运行记录由系统导出，不手工编辑。
- **来源要能打开**：引用的法规、判例、API 变化都先打开原始页面或可信的二手来源确认，并附链接。
- **安全清单逐项检查**：密钥只来自环境变量（`npm run check:secrets` 扫描源码与前端构建产物）；材料按数据处理；输出不加载外部资源。
