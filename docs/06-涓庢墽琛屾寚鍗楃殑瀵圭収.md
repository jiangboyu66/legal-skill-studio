# 与《执行指南与设计方案》的对照（v3）

> 对照对象：上传的《法律 AI 平台 Skill 与 Workflow 自助创建：完整执行指南与设计方案》（48 页）。该指南本身也是 AI 生成的文档（指南正文自述），因此下面对它的每条建议都做了核实与取舍，而不是照单全收。
> 处理原则：保留上一轮明确要求修复的能力（DAG、多用户治理、多格式物料），补齐指南指出而 v2 缺失的部分；偏离指南的地方写进 ADR。

## 1. 一句话结论

v2 与指南的主要差距不在“功能多少”，而在三处：**数据保护停留在“提醒”**、**结论核验被表述成“无需额外关注”**、**没有评测数据支撑版本比较**。v3 已逐项补齐；DAG、代理工具、TypeScript 技术栈三处是有意偏离，理由见 ADR。

## 2. 已经一致的部分

| 指南建议 | 本项目实现 |
|---|---|
| 声明式 Skill（说明 + 输入 + 输出 Schema），Schema 是步骤间契约 | Skill 配置 + 输出字段 → JSON Schema；`submit_output` 工具校验，三次不合规失败 |
| 版本不可变、运行记录可复现 | 发布即不可变版本；运行保存工作流、Skill、规则包快照 |
| 模型网关是唯一出口，可切换供应商，模拟模式 | `server/services/llm/`（Anthropic / OpenAI 兼容 / 模拟），其他模块不直接调用 SDK |
| 引用逐字核验 + 规则溯源 + 人工复核 | 引文与规则编号核对（含页码）、规则包来源与核实程度、逐条复核 |
| 密钥只来自环境变量 | 是；前端只拿到“是否已配置” |
| 澄清问题与假设、风险前置 | docs/01（v3 收敛为 5 个问题 + 假设隔离表） |
| 失败也是设计的一部分 | 统一错误结构（中文原因 + 处理建议）、自动重试、故障注入 |

## 3. 有意偏离（及理由）

| 指南建议 | 本项目选择 | 理由 | 记录 |
|---|---|---|---|
| MVP 只做线性 Workflow | 保留 DAG（条件、并行、审批节点） | 上一轮需求明确要求修复“只能线性”；条件分支与审批是法务真实流程。用静态校验与测试控制复杂度 | [ADR 0001](adr/0001-dag-workflow.md) |
| Python / FastAPI | Node.js + TypeScript 全栈 | 前后端共享类型，一条命令启动 | [ADR 0002](adr/0002-node-typescript.md) |
| 模型不给工具 | 只读、不联网的 4 个工具 | 长文档与“缺少披露”类问题需要按需查证；只读工具不新增外泄通道；组织可设为需确认 / 禁止 | [ADR 0003](adr/0003-read-only-agent-tools.md) |
| 规则包作为步骤参数 | 规则包是受审核的独立实体 | 能证明“依据谁在何时批准的哪一版规则” | [ADR 0004](adr/0004-governed-rule-packs.md) |
| 错误码 `E_*` 命名 | 沿用现有错误码，提供一一对应表 | 改名不改变行为，却会破坏已有测试与界面；对应关系见 docs/04 §3.3 | docs/04 |
| `model_config.temperature = 0` | 不发送采样参数 | Claude 4.7 及之后的模型对非默认的 temperature / top_p / top_k 返回 400，API 版本 2026-10-21 起对所有模型都返回 400（[迁移说明汇总](https://codersera.com/blog/anthropic-api-2026-10-21-sdk-migration-guide-2026/)）；稳定性改由 Schema 校验、引文核对与评测衡量 | docs/03 |

## 4. v2 的差距与 v3 的修复

| # | 差距（对照指南） | 严重性 | v3 的处理 | 验证 |
|---|---|---|---|---|
| 1 | 澄清问题 10 个，超过题目“不超过 5 个” | 违反硬性要求 | 合并为 5 个，新增假设隔离表 | docs/01 |
| 2 | 个人信息只告警，原值仍发给模型 | 高 | 发送前可逆假名化（NRIC/FIN、电话、邮箱、卡号），结果中还原；含个人信息的原件不发送 | S4：`governance.test`、`security.test`、e2e 15 |
| 3 | 材料用固定 `<input>` 标签，可被伪造闭合；无结尾重申 | 高 | 每次随机的 `<input-xxxxxxxx>` 边界 + 结尾重申 + 注入短语告警 | S1/S2：`security.test`、e2e 15 |
| 4 | 没有系统提示词泄露检测 | 中 | 一次性金丝雀 + 提示词指纹；泄露则 `POLICY_BLOCKED`，过程记录同样清除 | `security.test` |
| 5 | Markdown 输出中的外部图片会被浏览器请求 | 中 | 后置钩子移除；前端不渲染图片；CSP `img-src 'self'` | S3：`security.test`、e2e 15 |
| 6 | 无静态加密、无保留期、无启动自检、无健康检查、无密钥扫描 | 中 | `DATA_ENCRYPTION_KEY`（AES-256-GCM）、`RETENTION_DAYS`、启动自检、`/api/health`、`npm run check:secrets` + gitleaks | S6 与加密 / 保留期测试 |
| 7 | 核验代理判“支持”时显示“无需额外关注”——等于用 AI 核查 AI | 高 | 改为“优先复核 / 常规复核”，所有发现都需人工确认；OCR 近似匹配标为“需核实”不算通过 | `agent.test`、界面 ui-22 |
| 8 | 没有评测集与指标，无法比较 v1 / v2 | 高 | 10 份虚构物料（6 训练 / 4 留出）+ 期望问题 + 不应标记；召回、精确、F2、引文可核验率；一键评测；审核页显示评测对比 | `eval.test`、ui-26 |
| 9 | Skill 发布新版本会悄悄改变已批准的工作流 | 高 | 工作流版本钉住 Skill 版本，升级需重新审批 | `governance.test`、e2e 9 |
| 10 | 失败后只能整条重跑 | 中 | 从失败节点重试：同版本、复用已成功节点 | T8：`runs.test`、e2e 17 |
| 11 | 复核只有采纳 / 驳回 | 中 | 增加“修改后采纳”和“补充漏项”，计算 H，进入优化证据 | `runs.test`、e2e 16 |
| 12 | 法域只是 Skill 的标注 | 中 | 运行时输入；未指定时标注“（假设）”；与规则包不一致告警 | `runs.test` |
| 13 | 缺少 Mock 异常标记 | 低 | `[[MOCK:429]]`、`429_ONCE`、`TIMEOUT`、`BAD_JSON`、`FAKE_QUOTE`、`LEAK` | T7–T10：`runs.test` |
| 14 | 缺少受控自我优化 | 差异化 | 优化代理只看训练集失败与反馈 → 全量评测 → 门控 → 人工采用为草稿 → 照常审批 | `eval.test`、e2e 19 |
| 15 | 缺少 ADR、AI 使用说明、测试矩阵、运行记录导出、AGENTS.md、演示脚本 | 交付规范 | docs/adr、docs/ai-usage.md、docs/04 §3、docs/evidence/runs、AGENTS.md、docs/demo-script.md | — |

## 6. 指南中经核实后引用的事实

- [2025] SGHCR 33（Tajudin bin Gulam Rasul v Suriaya bte Haja Mohideen，2025-09-29）：律师引用 AI 生成的虚构判例，被命令个人承担 S$800 讼费（第 [99] 段）；第 [39] 段援引新加坡法院《生成式 AI 工具使用指南》第 5(3)(e) 段——不能用一个生成式 AI 工具去确认另一个工具的输出。来源：[eLitigation 判决书](https://www.elitigation.sg/gd/s/2025_SGHCR_33)、[IRB Law 评述](https://irblaw.com.sg/?p=1089813)。这是 v3 把核验改为“只决定复核顺序”的直接依据。
