# ADR 0003：Skill 以代理方式运行，可调用只读工具

- 状态：已采纳（v2）
- 与执行指南的关系：指南建议模型“不给工具”，以减少注入后的外泄通道。本项目给工具，但只给只读、不联网的工具。

## 背景
长材料、PDF 多页和“缺少某项披露”这类问题，需要模型按需翻页、搜索、查规则全文与适用渠道；把所有内容一次性塞进提示词既贵又不可靠。

## 决策
工具注册表只有 4 个只读工具（`read_document`、`search_document`、`lookup_rule`、`verify_quote`）加 `submit_output`；它们只能读取本次运行的材料和关联规则包，不能联网、不能写入。组织策略可把任一工具设为“需确认”（运行暂停等待审批）或“禁止”；每次调用都记录在“AI 过程”中。

## 备选方案
1. 不给工具：攻击面最小，但长文档与缺失类问题的质量差，也无法“查证后再引用”。
2. 给检索 / 浏览等外部工具：能力更强，但会引入外泄通道和不受控的信息来源。

## 代价
多轮调用增加成本与延迟（用最大轮次、预算、提示缓存控制）；注入成功时模型能读到本次材料——但本次材料本来就在上下文里，没有新增外泄路径。

## 何时重新评估
如果要接入外部法规数据库或写回文档管理系统，新工具必须单独评审，并默认设为“需确认”。
