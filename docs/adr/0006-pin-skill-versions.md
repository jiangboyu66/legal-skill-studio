# ADR 0006：工作流版本钉住 Skill 版本

- 状态：已采纳（v3）

## 背景
v2 中正式运行总是使用 Skill 的“最新已发布版本”。Skill 发布 v2 后，已经批准的工作流会悄悄改变行为——工作流审核人批准的并不是实际运行的内容。

## 决策
工作流提交审核时记录每个 Skill 当前的已发布版本（`pins`），批准时补齐，正式运行只按钉住的版本执行（从不可变版本表读取）。Skill 有更新版本时，运行给出 `SKILL_UPDATE_AVAILABLE` 提示，工作流编辑页显示“可升级”；重新提交工作流审批即升级，审核页显示新旧钉住版本。

## 备选方案
始终使用最新版本：少一次审批，但破坏“批准什么就运行什么”。

## 代价
升级 Skill 需要两次审批（Skill 与工作流）。对只改措辞的小版本，后续可以加“兼容更新自动升级”的组织策略。

## 何时重新评估
当工作流数量很多、升级频繁时，提供批量升级和影响面分析（哪些工作流使用该 Skill）。
