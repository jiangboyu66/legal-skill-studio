# ADR 0008：SQLite + 应用层加密 + 保留期

- 状态：已采纳（v3）

## 背景
原型需要零外部依赖、可一条命令启动；同时指南要求静态加密与数据保留期。

## 决策
继续使用内置 `node:sqlite`（WAL、迁移、按组织隔离的仓储接口）；设置 `DATA_ENCRYPTION_KEY` 后，文档、运行、评测、优化记录的 JSON 负载与上传的原件文件用 AES-256-GCM 加密（每个值随机 IV），开启前写入的明文仍可读取；缺少密钥或密钥错误时启动自检拒绝启动。`RETENTION_DAYS` 定期删除过期的已完成运行、评测记录和未被引用的文件，并写审计。

## 备选方案
1. Postgres + 磁盘 / 表空间加密：生产首选，但原型部署成本高。
2. SQLCipher：整库加密，但需要原生扩展，跨平台安装不稳定。

## 代价
密钥由环境变量提供，没有轮换；Skill、规则包、审计日志不加密（不含物料原文）；索引列（时间、状态）为明文。

## 何时重新评估
生产化时迁移到 Postgres，密钥交给 KMS 管理并支持轮换；仓储接口已隔离，业务代码不需要改动。
