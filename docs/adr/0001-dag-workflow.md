# ADR 0001：工作流采用 DAG，而不是线性步骤

- 状态：已采纳（v2）
- 与执行指南的关系：指南建议 MVP 只做线性 Workflow，把 DAG 留到后续。本项目保留 DAG。

## 背景
v1 只支持线性步骤。上一轮评审明确把“只能线性执行”列为需要修复的限制；营销物料审阅的真实流程里，高风险才需要深度审查、只有存在问题才起草补充材料请求、法务负责人审批之后才出最终意见——这些是条件分支、并行和人工节点。

## 决策
节点之间用 `needs` 声明依赖，`when` 写条件（受限表达式，不执行代码），独立节点有界并行，审批节点暂停运行直到指定角色决定；映射只能引用上游节点的字段，保存和运行前都做静态校验。

## 备选方案
1. 线性步骤 + “跳过本步”开关：实现简单，但并行和审批节点只能靠约定，难以校验。
2. 引入通用编排引擎（Temporal、n8n 一类）：能力强，但给法务创建者的心智负担和部署成本都过高。

## 代价
状态机更复杂；创建者需要理解依赖关系。缓解：流程图可视化、实时校验（环、未知依赖、条件引用非上游、字段不存在）、13 项工作流测试、重启续跑。

## 何时重新评估
如果试点中 90% 以上的工作流是线性的，可以默认隐藏 DAG 高级选项，只保留“线性 + 审批节点”的简化编辑器。
