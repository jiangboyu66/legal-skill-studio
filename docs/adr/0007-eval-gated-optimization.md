# ADR 0007：评测驱动的受控优化

- 状态：已采纳（v3）

## 背景
执行指南把“评测驱动的自我优化”作为差异化方向，同时强调必须防止过拟合与无人监督的自动发布。

## 决策
1. 评测集作为数据随仓库管理（`testdata/eval/`），分训练 / 留出；每个期望问题给出可接受的规则编号与原文锚点，另有“不应标记”清单。
2. 指标：召回、精确、F2、引文可核验率、未知规则率、“不应标记”命中、成本；综合分取 R(v) 中可计算的部分。
3. 优化代理只看到训练集失败与人工反馈（不含留出集），只改任务说明，不改输出结构与规则。
4. 候选在训练 + 留出上全量评测，门控：留出集综合分 +0.03、“不应标记”与错误不增加、说明长度 ≤ 120%。
5. 通过门控的候选只能由创建者“采用为草稿”，之后照常提交审核（四眼原则）。不自动发布、不在线学习、不微调。

## 备选方案
1. 只做评测、不做优化：最稳妥，但放弃了指南的差异化方向。
2. 自动采用通过门控的候选：更快，但绕过人工审核链条。

## 代价
10 个用例太少，指标波动大；标签未经律师复核。模拟模式下候选无法通过门控（输出不随说明变化）——这正好展示门控在起作用。

## 何时重新评估
评测集扩到 30–50 份并由律师复核后，再考虑引入 LLM 评审分 J 与成本 / 长度惩罚。
